## DRF-01

**Naming style differs from the rest of the repo**

Severity: low. Module: `drf`. Status: experimental.

**Why it matters.** Assistants default to their own naming habits. Code that names things differently from its neighbours is harder to read and search.

**How to fix.** Rename to match the repository's convention.

## DRF-02

**New library for a job the repo already covers**

Severity: medium. Module: `drf`. Status: experimental.

**Why it matters.** The repo already uses one library for this job. A second one adds a dependency and two ways of doing the same thing.

**How to fix.** Use the library the repo already uses, or agree on a migration in a separate change.

## DRF-03

**Idiom differs from the rest of the repo**

Severity: low. Module: `drf`. Status: experimental.

**Why it matters.** Examples: print() in a codebase that logs, or missing type hints where nearly every function has them. These are common signs of pasted, unadapted output.

**How to fix.** Follow the repo's pattern: use its logger, add the type hints.

## HAL-01

**Imported package does not exist on PyPI**

Severity: high. Module: `hal`. Status: stable.

**Why it matters.** AI assistants invent plausible package names. Installing a name that does not exist fails, and an attacker can register it and ship malware (slopsquatting).

**How to fix.** Check the import. Use the real package name, or remove the dependency.

References: CWE-829, LLM03:2025 Supply Chain

## HAL-02

**Imported package was published very recently**

Severity: medium. Module: `hal`. Status: experimental.

**Why it matters.** Attackers register names that AI assistants tend to invent. A package whose first release is only days old, and that you did not choose on purpose, deserves a look.

**How to fix.** Check the package's repository, maintainers and download history before using it, or pin a library you already trust.

References: CWE-1357, LLM03:2025 Supply Chain

## HAL-03

**Imported package name is one typo from a popular package**

Severity: medium. Module: `hal`. Status: stable.

**Why it matters.** Typosquatting packages copy a popular name with one letter changed and ship malware. Assistants can reproduce those misspellings.

**How to fix.** Compare the import with the popular package it resembles and use the real name.

References: CWE-1357, LLM03:2025 Supply Chain

## HAL-04

**Import not declared in the project's dependencies**

Severity: medium. Module: `hal`. Status: stable.

**Why it matters.** The code imports a third-party package that no requirements file or pyproject dependency list mentions, so a clean install will fail.

**How to fix.** Add the package to your dependency manifest, or remove the import.

## INC-01

**Placeholder comment left by an AI assistant**

Severity: medium. Module: `inc`. Status: stable.

**Why it matters.** Comments such as 'rest of code here' mark code an assistant skipped. The surrounding function is usually incomplete.

**How to fix.** Write the missing implementation, or delete the comment if nothing is missing.

## INC-02

**Hollow function body**

Severity: medium. Module: `inc`. Status: stable.

**Why it matters.** A function whose body is only `pass`, `...` or `raise NotImplementedError` does nothing. AI-generated code often leaves these behind as stubs.

**How to fix.** Implement the function, or mark it as an abstract method or protocol member.

## INC-04

**Swallowed exception**

Severity: medium. Module: `inc`. Status: stable.

**Why it matters.** An except block that only passes hides failures, so bugs surface later and far from their cause.

**How to fix.** Log the error, re-raise it, or handle it explicitly; catch the narrowest type.

References: CWE-390

## INC-05

**Assistant chat text inside source**

Severity: high. Module: `inc`. Status: stable.

**Why it matters.** Markdown fences or sentences like 'Here is the updated function' were copied from a chat window into the file.

**How to fix.** Delete the conversational text so only code remains.

## INC-06

**High TODO or FIXME density**

Severity: low. Module: `inc`. Status: stable.

**Why it matters.** Many TODO, FIXME or HACK markers in one file point to unfinished work.

**How to fix.** Finish or ticket the open items, then remove the markers.

## INC-08

**File does not parse**

Severity: high. Module: `inc`. Status: stable.

**Why it matters.** The file has a syntax error. Truncated AI output often ends mid-function or with an unclosed bracket or string.

**How to fix.** Restore the missing part of the file, or regenerate it in full.

## LLM-01

**Untrusted input reaches the prompt of a model call**

Severity: high. Module: `llm`. Status: stable.

**Why it matters.** Text from users, web pages or the command line was placed where the model treats it as instructions (the system prompt) or glued into a prompt string. An attacker can override your instructions (prompt injection).

**How to fix.** Keep instructions constant. Send untrusted text only as a user message or inside clearly delimited data, and validate or limit what the model's answer can trigger.

References: CWE-77, LLM01:2025 Prompt Injection

## LLM-02

**Model output passed to eval, exec or compile**

Severity: critical. Module: `llm`. Status: stable.

**Why it matters.** Whatever the model returns can be steered by prompt injection. Executing it as code gives an attacker code execution in your process.

**How to fix.** Never execute model output. Ask for structured data (JSON), parse it with json.loads or ast.literal_eval, and validate it against a schema.

References: CWE-95, CWE-94, LLM05:2025 Improper Output Handling

## LLM-03

**Model output passed to a shell or subprocess**

Severity: critical. Module: `llm`. Status: stable.

**Why it matters.** Model output used in a command line lets prompt injection run arbitrary commands on the host.

**How to fix.** Choose from an allow-list of fixed commands, pass arguments as a list with shell=False, and validate every value the model supplies.

References: CWE-78, LLM05:2025 Improper Output Handling

## LLM-04

**Model output used to build a SQL query**

Severity: high. Module: `llm`. Status: stable.

**Why it matters.** A query built from model output can be steered into reading or destroying data it was never meant to touch.

**How to fix.** Use parameterised queries with fixed SQL, or map the model's answer to a fixed set of allowed queries. Run the model's database user with read-only rights.

References: CWE-89, LLM05:2025 Improper Output Handling

## LLM-05

**Model output used as a file path**

Severity: high. Module: `llm`. Status: stable.

**Why it matters.** A path chosen by the model can point anywhere on disk, including secrets or system files, and can overwrite or delete them.

**How to fix.** Resolve the path against a fixed base directory, reject anything that escapes it, and prefer an allow-list of file names.

References: CWE-22, LLM05:2025 Improper Output Handling

## LLM-06

**Model output used as a request URL**

Severity: high. Module: `llm`. Status: stable.

**Why it matters.** A URL chosen by the model can target internal services or cloud metadata endpoints (server-side request forgery).

**How to fix.** Allow-list hosts, block private and link-local addresses, and fetch through a proxy with no access to internal networks.

References: CWE-918, LLM05:2025 Improper Output Handling

## LLM-08

**Agent tool gives the model unrestricted capabilities**

Severity: high. Module: `llm`. Status: stable.

**Why it matters.** The model chooses tool arguments, and a prompt-injected model chooses hostile ones. A tool that runs commands or code, or passes arguments to files, SQL or the network unchecked, hands that control to whoever can influence the prompt.

**How to fix.** Give each tool one narrow job with a fixed allow-list of actions, validate every argument against a schema, and run tools with least privilege in a sandbox.

References: CWE-269, LLM06:2025 Excessive Agency

## LLM-09

**Destructive agent tool with no confirmation step**

Severity: medium. Module: `llm`. Status: stable.

**Why it matters.** The tool deletes or drops data, and nothing asks a person to approve the action first. One bad model decision is then irreversible.

**How to fix.** Require human approval before destructive actions, or add a dry-run mode that the model must call first.

References: CWE-862, LLM06:2025 Excessive Agency

## LLM-12

**Model call with no output token limit**

Severity: low. Module: `llm`. Status: stable.

**Why it matters.** Without a cap on output tokens, one long or looping answer can run up cost and latency, and an attacker can trigger it on purpose.

**How to fix.** Set max_tokens (or max_completion_tokens / max_output_tokens), plus a request timeout and a per-user rate limit.

References: CWE-400, LLM10:2025 Unbounded Consumption

## REG-01

**Test that passed before now fails or is missing**

Severity: high. Module: `reg`. Status: stable.

**Why it matters.** The change broke behaviour the existing test suite protected.

**How to fix.** Fix the code, not the test. If the behaviour changed on purpose, update the test and say so in the review.

## REG-02

**Tests deleted, skipped or weakened**

Severity: high. Module: `reg`. Status: stable.

**Why it matters.** Assistants sometimes make a failing test pass by deleting it, skipping it or removing assertions, which hides the bug instead of fixing it.

**How to fix.** Restore the test or assertion and fix the code. If a test is truly obsolete, remove it in a separate, explained change.

## SEC-01

**Hardcoded secret or API key**

Severity: critical. Module: `sec`. Status: stable.

**Why it matters.** Credentials committed to source are copied into every clone, build and log. AI assistants often paste example keys that turn out to be real ones.

**How to fix.** Remove the value, rotate the credential, and read it from an environment variable or a secrets manager.

References: CWE-798

## SPC-02

**Requirement not met by the code**

Severity: high. Module: `spc`. Status: experimental.

**Why it matters.** A requirement in the spec has no matching implementation, or only a partial or empty one. AI assistants often skip or only half-build part of a request.

**How to fix.** Implement the missing behaviour, or remove the requirement from the spec if it was dropped on purpose.
